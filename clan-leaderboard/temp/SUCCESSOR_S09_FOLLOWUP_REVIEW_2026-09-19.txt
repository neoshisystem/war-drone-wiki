--------------------------------------

Before accepting an incoming snapshot as canonical:

1. Screenshot inventory
   - archive count
   - leaderboard/profile split
   - duplicate detection
   - archive hash if retained

2. Snapshot metadata
   - captured_at_utc
   - local date/time
   - member count
   - boundary marker
   - timestamp-derived league week
   - explicit boundary conflict check

3. Identity
   - player_id for known identities
   - explicit new identity flag for genuine new IDs
   - rename review
   - returning-player review
   - ambiguity = STOP, never guess

4. Membership
   - active intervals
   - removed intervals
   - return intervals
   - current-membership count vs observation count

5. Raw observation
   - every required raw field present
   - no derived values substituted as raw
   - reconstruction exceptions explicitly identified

6. Period Delta
   - current vs immediate previous valid observation
   - new identity semantics
   - removed identity semantics
   - negative-delta policy check once Project Authority defines it

7. Weekly
   - derive league week from timestamp + reset
   - do not infer week solely from report title
   - confirm same-week vs boundary behavior

8. Lifetime/Cumulative
   - preserve stable identity history across gaps
   - do not confuse cumulative with weekly

9. Registry metadata
   - current active identity => last_seen_snapshot must equal current snapshot
   - current display_name is current registry name
   - rename history reviewed separately

10. Provenance
   - source archive/hash
   - identity exceptions
   - reconstruction exceptions
   - reviewer decision notes

11. Publication
   - dry-run first
   - controlled --write
   - generate report from the canonical generator
   - generate archive from index
   - verify snapshot/index/report/archive consistency

12. Validation
   - canonical validator
   - performance tests
   - report generation test
   - archive test
   - E2E/publish test
   - add explicit regression for last_seen invariant

13. Post-merge
